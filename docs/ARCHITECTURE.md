# Architecture and behaviour

The app is static HTML, CSS and JavaScript. `app.js` renders hash routes into the main region; the audio element and persistent player remain outside that region so browsing does not replace playback.

## Routes and state

Discover filters the catalogue. My shelf combines browser-local saved and owned IDs. Record detail exposes side and track selection. Listening focuses the current record. Support is an alias for the October listening-budget walkthrough. Wireframes include an annotated page and the interactive `?wireframe=1` mode.

`porto-saved` and `porto-owned` store arrays in localStorage. `porto-shelf-seed-v1` seeds the original collection once; `porto-catalog-v2` adds the six later records once. `porto-catalog-v3` adds only the five artist editions once, preserving older removals and demo purchases. Removals persist after migration. Reset restores the whole collection and clears demo ownership. Storage is not an account or backend purchase record. Collection state uses localStorage, with no cookie or server account required. Records stay on the same browser and origin until removed or browser data is cleared. IDs are validated and deduplicated; saved and owned values are parsed independently so one malformed value does not reset the other. Rendering does not write storage. User changes persist immediately, and storage events update other open tabs. If storage is blocked or full, the app keeps the change for the current visit and explicitly reports that it was not saved persistently.

## Collection actions

Use the full Add to collection label as a primary action on artist cards, every record in the index, sleeves, record details and listening. Keep the same action in the fixed player at desktop and mobile sizes. The selected record is shown as In collection after saving, with an accessible remove label. Owned demo copies remain included and show a disabled collected state; a save action never grants ownership. My collection shows the union of saved and demo-owned IDs.

Saving from a music screen updates the collection controls in place, preserving keyboard focus and current playback. Removing from the collection view rerenders the shelf and focuses the main region. The existing fourteen starter records remain saved; this change does not clear or reseed anyone’s collection.

## Playback

The initial selection is Reformat from the fictional Kiki Static catalogue. Playback waits for the listener to press play; initialization loads no audio source. The older catalogue remains available without altering its credits or collection state.

`queueTrack` adds any album, side and track to the session queue without replacing the current track. `playQueuedTrack` consumes the queue in order before normal side progression resumes. `source` selects a local WAV or MP3 file. The timeline follows the media duration, with declared duration as a loading fallback; every listener can seek in the fixed player. Automatic progression stops at the end of a side. A request counter prevents stale play promises from restoring UI state after a pause or new selection.

The live badge is simulated. It pulses after `playing`, and stops on waiting, stalled, loadstart, pause, error or ended events. The badge displays the fictional node identifier LND-001 and DEMO NODE. Audio-event handling demonstrates player state, not peer-to-peer delivery or network attestation.

## Assets and rights

Three releases use original synthesized 24-second WAV studies. Six use Kevin MacLeod recordings divided into consecutive MP3 chapters. Five artist editions add fifteen distinct full-length Kevin MacLeod recordings, normalized to a -16 LUFS target and encoded as 128 kbps MP3. Each edition has two tracks on side A and one on side B; all counting, side completion and navigation use actual array lengths. `audio-credits.json` records their real titles, sources, licence URLs, modifications and durations. Each ZIP includes attribution. Generated artwork and fictional packaging are separate from the real music credits.

## Artist editions and discovery

`artist-editions.js` loads before the application and supplies fictional artist metadata, square generated cover assets, per-track attribution and actual audio durations. Discovery uses one featured digital vinyl hero and a readable cover grid. Search and a genre selector filter the grid. The existing vinyl shelf remains in Collection, and record details expose the gatefold through an explicit button. Search matches artists, record titles, genres and track names. The art directions span Hyperpop, Indie, Alternative, Rock and R&B; the audio is instrumental demo music with related textures, not original performances by those fictional artists.

`docs/music-provenance/2026-09-20.json` records direct source links and original/downloaded file hashes. `scripts/import-catalogue-music.py` rebuilds audio and credits from the selected source catalogue. If re-importing, synchronize updated durations and credit entries in `artist-editions.js` and regenerate any modified credit-page text before validation.

## Purchase presentation

`buyingOptions` renders physical vinyl before digital-only purchase controls on every record. `purchase(id, format)` opens the vinyl destination explanation or the digital demo confirmation. The catalogue has no connected physical retailers or stock, so the vinyl path has no external checkout and never writes ownership. Only the explicit digital confirmation updates `porto-owned`. Existing demo ownership preserves credited downloads. Saving remains independent of ownership.

## Evidence limits

There is no payment provider, user account service, persistent rights registry, live Porto node, streaming attestation or settlement implementation. Sequential files may have transitions between chapters; this is not verified gapless native playback. The responsive web layout has no TestFlight, App Clip or installable iOS package.

## Artist routes and journal

`#artists` renders the directory; `#artist/<artist-slug>` renders a profile or a helpful not-found state. Artists are deduplicated by name and grouped across releases. The directory has independent search and genre state, so returning from a profile preserves the chosen search. Profile category state resets on changing artists. The profile links from Discover, record details and Listening connect these routes.

`artist-editions.js`, `artist-profiles.js` and `app.js` load in order as classic scripts at the end of the document. Profile functions use the catalogue and playback helpers after app initialization. The artist profile data is a prototype source model: image entries have a local source, alternative text, title and caption; note entries have a title and body. Categories and grid length derive from each artist's items. The initial examples are fictional and share three generated scene assets. No user content is accepted and no authoring backend exists. Source strings are escaped before insertion in artist templates.

Play the music starts the artist's record without leaving the profile. Rendering the directory, filtering the grid and opening the detail dialog never replaces the audio element or changes its source. The dialog uses browser focus trapping and Escape dismissal, with a descriptive title and focus return. Navigating away closes it. Record collection controls retain the existing local collection behaviour.

The retention hypothesis is that artist-selected context gives listeners a reason to explore while music continues. No measured retention claim, engagement counters, algorithmic feed, social actions, new analytics or notifications are introduced.

## October routes, model boundary and data

`october.js` loads before `app.js`, defines route renderers and initializes after the existing player. `#home` (the default, rendering the feed), `#original` (Reformat), `#original/<source-key>`, `#search`, `#studio`, `#variation/<id>`, `#feed`, `#creator/<id>`, `#you`, `#budget` and `#ledger` are the new surfaces. `#support` aliases budget. Existing record, artist, collection and listening routes remain. If the current item is a concept preview, Listening opens its variation surface.

Eight supported source songs use in-memory track records with explicit audio files and decoded full-length durations from `reformat-audio.js` and `feed-audio.js`. Originals reference existing licensed catalogue recordings; each source has four separate full-length conventional DSP adaptations. The sources table binds a song to its release, artist, cover, original and prepared files. Twelve fictional creators and 25 seeded variations populate an interleaved feed. Genre filtering applies to rotation and community posts; artist discovery exposes all fourteen catalogue artists. The feed cards use precomputed original-source waveform amplitudes and update their highlighted progress on timeupdate. Feed versions are not inserted into the fourteen-record catalogue or its ownership IDs. `source()` supports explicit fixture files; `resume()` checks the demo budget before allowing a variation. Ordinary catalogue playback, original previews and queue priority are preserved. Page navigation never replaces the audio element. Playback does not update the example balance or ledger.

`porto-reformat-v2` holds validated variations, source keys, parent IDs, publish flags, creator follows, track saves and illustrative budget state. A saved variation must reference an existing parent, a supported effect recipe and a validated local ID. Numbering is scoped to each source song. Reformat seeds reserve 002 to 009; other sources reserve 002 to 008. Locally created versions receive the next unused integer for that source. Load derives the source from the validated parent, ignoring an inconsistent stored source. Older drafts without a source inherit Reformat through their existing parent chain. Load validates uniqueness and assigns numbers to older drafts in their saved order. Numbering does not alter the stored ID, source audio or lineage. The display title is @handle / userTitle, with mood kept as metadata and the original song retained as source credit. Local userTitle values are whitespace-normalized, limited to 64 characters and escaped wherever inserted into HTML. Creation opens the title form; Rename edits the same local record and synchronizes the current player title. Older records without userTitle fall back to Untitled NNN without fabricating a chosen name. Seeded fictional versions have authored title fixtures. Numbering still determines artwork and does not change on rename. Artwork is a deterministic CSS composition keyed by edition number and preset: a transformed source image, colour layers, geometric marks and a creator-handle stamp. Presets add static blur/double exposure, clipped glitch bands, directional smear or SVG displacement. Filter definitions live once in the document shell, and only image layers receive the effects; text and controls stay sharp. The same identity appears in cards, search, the track page, sharing, lineage, ledger and the persistent player. Invalid IDs, unknown creators and unsupported presets are discarded on load. No raw prompt text is persisted. Local creation is bounded to 30 versions. Text rendering escapes input; custom model output is not accepted. Cross-tab storage events refresh state and pause a variation when a new cap blocks it. Private source documents are not bundled.

`voice-input.js` creates a new browser SpeechRecognition instance only after a click or tap. Starting and listening pulse visibly; interim results rebuild the editable transcript from the complete result list to avoid duplication. Stop finishes the transcript; cancellation invalidates late callbacks and aborts the service. Permission, network and availability errors survive the service end event. Startup times out after 12 seconds and listening ends after 60 seconds, with no auto-restart. Switching tracks, navigating away, hiding the page, typing or submitting cancels capture. Opening voice input and using the player transport do not interrupt listening or cancel capture. Browser speech can use its provider’s remote recognition service; no service key or Porto speech server is configured. Old Afterlight storage is preserved under its original key, with no cross-song migration. Supported text requests create effect settings and preserve source lineage. Local publish requires its own confirmation and is idempotent. The artist-permission panel describes fictional permissions, not an authorization check against a live rights registry. Creator credit is distinct from a royalty allocation.

GBP ledger examples are separate from the listening-budget fixture. A proposed future payout record references the Aptos/USDC target without representing GBP as a USDC amount or inventing a transaction. No model, payment, wallet or chain is connected. Browser speech is the only optional external service.

## Genealogy, live effects and local counts

Original and variation routes now render the complete source family as nested semantic lists with visual connectors. Source-scoped seed and local versions form a validated acyclic tree rooted at the original. All local drafts are visible, alongside seeded published siblings. Clicking a node selects its family detail; clicking its Play control starts that version. Source browsing remains silent. Create opens the voice/text command sheet.

`vendor/tone-15.1.22.js` and its MIT licence are vendored from the published npm package, with a recorded bundle hash. `audio-warp.js` selects pre-rendered MP3s synchronously for all seeded variations. Custom versions warm through Tone.js offline rendering after creation and on reload, with native playback reserved for explicit play requests. Pitch, filtering, distortion, tremolo, echo and limiting are baked into a WAV before native HTML media playback. The media element never connects to a MediaElementAudioSourceNode or a live effects graph. Speed uses native playbackRate with pitch preservation. The play-request token prevents completed renders from starting a superseded request.

Rendered versions read the original audio file, not a doubly processed prepared edit. Original-source waveform envelopes describe source position, not the post-effect signal. When Tone.js is missing, existing prepared versions remain playable; prepared audio remains the fallback; custom rendering requires the bundled library. Runtime audio errors retain the existing play failure feedback. Live speed is bounded to 0.65–1.4, pitch to ±12 semitones, tone to 300–20,000 Hz, distortion to 0–0.8 and echo wet mix to 0–0.65. Settings are sanitized after prompt interpretation and on reload. Submitting a supported command creates a new numbered child and preserves parent settings. Downloaded prepared MP3s do not contain custom live edits.

`porto-reformat-v2.plays` stores validated non-negative local counts per track ID. Seed totals are deterministic illustrative fixtures, explicitly labelled in the family view; drafts have no seeded plays. The event observer accumulates small forward media-time deltas adjusted for playback speed while unpaused, ignoring seeks and large jumps. It counts once per loaded session after min(30 seconds, half duration), persists the result and updates visible counts. Reloading restores totals, while resetting the walkthrough clears local counts. Cross-tab updates use the existing storage refresh; simultaneous writes can race, so these counters are not production analytics or attested/billable streams. Financial examples never read them.

## Persistent voice/text input

`#oct-voice-sheet` is a native nonmodal dialog outside the route-rendered main region. Only this sheet contains `#oct-prompt-form`, preventing duplicate prompt IDs or route rerenders from destroying the input. `openSheet(true)` opens it and invokes the speech controller in the click gesture; `openSheet(false)` focuses text only. The persistent command dock lives outside the player and remains visible at the bottom at desktop and mobile breakpoints. The player sits above it. Close events cancel recognition, restore trigger focus and clear expanded-state attributes. Hash navigation closes the sheet. The panel sits above the player, leaving transport controls usable. Escape and the close button dismiss it and restore trigger focus.

All numeric sound controls and temporary slider-preview state are removed from the product. `PortoWarp.parseRequest` validates the full supported command, applies effect changes to a sanitized copy of its parent, and rejects unrecognized remaining words. Relative speed and pitch requests inherit prior settings. Additional effect-only edits use Custom metadata, while named mood requests retain their mood tags. Stored custom settings migrate unchanged. Normal playback configures the effect chain from saved version settings only. The voice and text paths share submission and never auto-submit a transcript or auto-play a new version.

## Spatial genealogy

`genealogy-graph.js` assigns deterministic three-dimensional positions from each song's real parent-child tree and renders a perspective SVG graph. Orbit controls project those positions without altering lineage. Nodes embed the shared version artwork within a circular SVG foreignObject. Nodes include native SVG creator images with circular clips, separate from the artwork layer. Node selection navigates directly to a detailed track route, with the selected track above its lineage; the semantic version list remains available for full details and playback. Resizing reprojects the active graph; no animation loop or external graph service runs. Royalty examples are deterministic per-track fixtures, summed once across the family, with local drafts at zero. They are independent of stream counts, budgets and ledger examples.

## Playback transport, 12 October 2026

Opening voice input preserves the current media position and playback state. The shared player offers play/pause, stop and a native range input for seeking within the current track, including pointer, touch and keyboard interaction. Stop pauses and returns that track to zero without changing the queue. Seeking never starts paused audio, changes the selected track or requires ownership. Metadata-pending seeks are retained until loadedmetadata, and cleared on source changes or stop. Elapsed/remaining time and accessible value text use the current track duration and effective playback rate. Transformation controls remain voice/text only; the timeline changes playback position, not sound settings.

## Rendered audio edits and discussion

The effect settings add bounded reverse, chop and crush fields, defaulting to zero for older stored versions. ToneAudioBuffer decodes the local licensed source and reverses it when requested. Chop rearranges and repeats 180ms groups with 4ms edge fades. Interleaved 16-bit WAV object URLs retain the source duration and play through the shared HTML media element, preserving seeking, pause and stop. Bitcrushing uses a 4-bit PCM quantizer, avoiding a live AudioWorklet. Tone.js renders sine-wave Tremolo, other requested effects and a limiter before playback. Two rendered sources are cached; eviction avoids the actively playing URL. Buffers are disposed after encoding. This prepares DSP edits, not model output or instrument separation.

The play-request token guards asynchronous decoding so cancelled or superseded work cannot change the active media source. Source preparation is skipped on resume of the same recipe, preserving the selected position. Normal source changes clear the prepared key. Wild versions refuse playback if the effect library is unavailable rather than playing an unrelated fallback.

Comment fixtures are deterministic per seeded version and use fictional creator IDs. `porto-reformat-v2.comments` stores only local user text and creation times keyed by validated track ID, bounded to 50 items per track and 300 characters each. Rendering escapes all comment text; invalid stored entries are discarded. Posting updates only the discussion section, preserving audio and the graph view. Feed comment links open the matching variation and scroll to its thread. No API, account, moderation or messaging service is connected.

## Mobile audio processing, 12 October 2026

Following reports of continuous popping in iPhone Safari, originals start through native media playback without constructing an effects graph. Once Web Audio is needed, its context requests playback latency with 150ms scheduling look-ahead. Each version creates only its required processors; changing recipes disposes the previous nodes, and returning to an original removes all effects. BitCrusher and Tremolo therefore run only for versions that request them. Chopped versions retain the rendered slice edits, with smooth sine tremolo instead of hard square-wave modulation. The effects limiter leaves 3dB of headroom.

Audio progress updates only the current waveform and resets the previous one once. It changes bar classes only when the playhead crosses a bar, avoiding repeated work across the whole feed. Control labels update on transport changes, not every progress tick. This is a mitigation for mobile audio workload, not proof of pop-free output on a physical iPhone; device listening still needs confirmation.

## Native playback for all versions, 12 October 2026

After crackling was also reported in Chrome, effects rendering was moved entirely ahead of playback. This supersedes the earlier live effects path and mobile buffering mitigation. Tone.js Offline renders pitch, filter, distortion, sine tremolo, echo and limiting. Reverse, faded slices and 4-bit quantization operate on the decoded samples. The resulting 16-bit WAV retains the source duration and is played by the native HTML media element, with native speed and pitch preservation. Originals play their existing MP3 directly, even after a variation. No MediaElementAudioSourceNode, live BitCrusher worklet or effects graph remains attached to playback.

Renders are serialized, cancellation is checked before and after expensive stages, and every temporary node, decoded buffer and offline context is disposed. A cache keyed by source and complete settings retains two results, preserving the active URL during eviction. The first listen to a version can take longer to prepare; replay uses its cached file. Play/pause, switching, voice capture and waveform seeking continue through the shared player. Browser rendering and state tests do not establish pop-free output on the user's physical phone; a fresh listening check remains necessary.

## Track switching and play gestures, 12 October 2026

Ready originals and cached variations now prepare synchronously so native play is called within the listener's tap. Cached versions bypass queued rendering work. An uncached variation primes the same audio element with an immediate play/pause inside that gesture before awaiting its render; the requested version starts only if its request remains current. No playback is primed during page load or track-detail navigation. Track controls show Preparing while rendering and still allow cancellation. Tests cover synchronous starts, cached switching during a pending cancelled render, pause/resume and stale completion protection. Browser checks verify transport and source changes; physical iPhone behaviour still requires device confirmation.

Offline effects use an explicit context for every node and schedule all events upfront. Rendering advances Tone's preparation clock without per-second timer yields, avoiding long preparation waits when browsers throttle timers. Native audio rendering still completes asynchronously; serialized jobs retain the memory bound.

## Prepared catalogue and persistent audio cache, 12 October 2026

All 57 seeded variations ship as MP3 files rendered with the same Tone.js recipes as custom versions. Playback selects these files synchronously, including without Tone.js loaded; their native playback rate retains each recipe's speed. Pause/resume reuses the current media source and position, with no load, render or Preparing state. Preparing is reserved for asynchronous custom audio preparation.

On first visit, a service worker downloads every catalogue track in the background with two concurrent requests. It caches full files persistently and answers byte-range requests for Safari playback and scrubbing. Cached tracks need no audio network request. First downloads still depend on the network; browser storage restrictions or eviction fall back to streaming. Cache progress is available in document data attributes for verification and never implies downloaded audio before completion. Custom versions warm after creation and on reload; rendered WAVs persist in a separate browser cache, while only two object URLs remain resident. Initial page load and cache warming never play audio.

Regenerate seeded audio with scripts/render-catalogue.py and its loopback Render catalogue page; --resume retains verified completed files. FFmpeg only encodes Tone's rendered PCM as 128 kbps MP3. The prepared-audio.js manifest records source file, complete settings, output hash and size. All edits retain Kevin MacLeod / CC BY 4.0 attribution and the existing source credits. Validate all 57 files with validate-prepared-catalogue.mjs, transport with validate-player.mjs and validate-wild-audio.mjs, and range caching with validate-audio-cache.mjs.
